# Auditing and importing legacy LLM-DNA responses

Legacy response folders are potentially useful raw observations, but they are not trusted merely
because a `responses.json` file exists. DistDNA audits them against a destination collection
manifest and imports only a complete collection with explicit generation seeds and immutable model
revisions.

## Supported source layout

The importer recognizes the experiment-branch convention:

```text
out/rand_chinese/
  org_model-a_t02_p08_r1/responses.json
  org_model-a_t02_p08_r2/responses.json
```

`t02` means temperature `0.2`, `p08` means top-p `0.8`, and repeats are one-based by default. Each
`responses.json` must contain an `items` array with exact prompt text and non-empty response text.
The actual seed and model revision may appear on the root object, the item, or its `metadata`:

```json
{
  "generation_seed": 42001,
  "model_revision": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "items": [
    {"prompt": "Exact manifest prompt text", "response": "Visible response text"}
  ]
}
```

An old file without these fields remains useful for exploratory archaeology, but it is quarantined
and cannot enter the paper pipeline as a reproducible generation.

## Destination manifest requirements

Use a dedicated import manifest. It must enumerate the complete model, setting, prompt, and repeat
grid and opt into externally seeded records:

```json
"metadata": {
  "allow_external_seed_records": true,
  "model_revisions": {
    "org/model-a": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  }
}
```

Every revision must be the exact lowercase 40-character commit SHA used for generation. Do not
substitute a model's current Hub revision for an unknown historical revision.

Directory-safe model names are resolved automatically when unambiguous. For other names, provide
an explicit alias file:

```json
{
  "student-directory-token": "org/model-a"
}
```

## Audit first

```bash
distdna audit-legacy \
  --source-dir /path/to/LLM-DNA/out/rand_chinese \
  --manifest configs/legacy-import.json \
  --model-aliases configs/legacy-model-aliases.json \
  --output out/legacy-audit.json
```

The command exits nonzero unless every expected generation key is present and provenance-safe. The
report includes error codes, counts, observed models/settings, and a bounded preview of missing
keys. It never writes a response cache.

## Atomic import

After the audit reports `ready_for_import: true`:

```bash
distdna import-legacy \
  --source-dir /path/to/LLM-DNA/out/rand_chinese \
  --manifest configs/legacy-import.json \
  --model-aliases configs/legacy-model-aliases.json \
  --cache-dir data/legacy-import/responses \
  --audit-output data/legacy-import/audit.json
```

Import refuses an existing destination and publishes the cache only after all records validate.
Each record retains the real external seed, exact revision, source-relative path, source repeat, and
SHA-256 hash of its originating `responses.json`. Imported files use `seed_scheme: external`, so
they cannot be confused with responses generated by DistDNA's deterministic seed derivation.

The imported cache then uses the normal paper-faithful path:

```bash
distdna encode-responses \
  --manifest configs/legacy-import.json \
  --cache-dir data/legacy-import/responses \
  --encoder sentence-transformer \
  --encoder-model sentence-transformers/all-mpnet-base-v2 \
  --output-dir data/legacy-import/embeddings
```

The hashing encoder remains diagnostic-only. Legacy 128-D DNA vectors or character-hashing MMD
features are not imported; response text is re-encoded under the frozen paper encoder.

## Scale gates

Do not launch a 100/300-model matrix merely because an audit succeeds. Progress through these gates:

1. Complete the small model cohort with no missing cells.
2. Run point, mean, exact-MMD, and RFFTrace methods over identical budgets.
3. Verify non-ceiling retrieval and report RFF-to-exact-MMD correlation/error.
4. Repeat seeds and confirm results are stable.
5. Expand the model cohort only after the artifact schema and scientific comparison are frozen.

`distdna summarize` reports the single-run gates under `pilot_checks`; `distdna aggregate` reports
the repeated-seed decision under `scale_readiness`. The checks detect the previous pilot's all-1.0
ceiling without encoding a requirement that the proposed method must win.
